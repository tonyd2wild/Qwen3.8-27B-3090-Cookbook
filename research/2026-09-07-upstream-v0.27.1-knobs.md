## Qwen3.8-27B on 2x3090, vLLM v0.27.1: KV-pool levers

Base for all vLLM refs: `https://github.com/vllm-project/vllm/blob/v0.27.1/`. Numbers marked **M** are measured (Tony's repos, fleet notes, cited issues); **E** are my arithmetic from the source.

**Architecture facts (drive everything below).** The checkpoint is hybrid: 48 `linear_attention` (Gated DeltaNet) + 16 `full_attention` layers, `full_attention_interval: 4`, `mamba_ssm_dtype: float32`, no sliding window, 4 KV heads x 256 head_dim, `tie_word_embeddings: false` (HF config.json of `Vishva007/Qwen3.8-27B-W4A16-AutoRound`). vLLM reads `layer_types` in `vllm/model_executor/models/qwen3_5.py` L251 and inherits `mamba_ssm_dtype` into `--mamba-ssm-cache-dtype` when the flag is `auto` (`vllm/model_executor/models/config.py` L799-823). So yes, the flag applies at v0.27.1.

### Notes

**KV dtype on sm_86.** With `fp8`/`fp8_e4m3`, FlashAttention is rejected ("FP8 KV cache requires FA3 on SM90 or FA4 on SM100", `flash_attn.py` L214-224; `fa_utils.py` L296-316) and FlashInfer is selected next in priority (`cuda.py` L156-162; `flashinfer.py` L345-351, L468). Storage-only: 1 B/token, attention upcasts. `fp8_e5m2` is never FA-supported (L304), FlashInfer only, same bytes, worse precision. Scales are 1.0: `calculate_kv_scales` is deprecated and force-disabled for hybrids (issue #37554, `config.py` L451-462). Club-3090 measured fp8_e4m3/FlashInfer at 114 tok/s @1K, 115 @35K on Qwen3.5-27B (**M**); `int8_per_token_head` (Triton only) fell 130.8 -> 50.7 tok/s at 35K; TurboQuant raises NotImplementedError on hybrids. You are already at the safe floor.

**Hybrid block alignment (why the pool looks the way it does).** Attention block size is bumped so one attention page >= one mamba page, then the mamba page is padded to match (`platforms/interface.py` L899-936). Here: attention = 1024 B/token/rank, mamba page 1,675,264 B -> block size 1648 tokens (bf16 SSM -> 880). Boot log lines to check: "Setting attention block size to N tokens", "Padding mamba page size by X%", and "Add N padding layers, may waste at most X%" (`kv_cache_utils.py` L1245-1266). The reported pool is group-aware: `concurrency x max_model_len` (`kv_cache_utils.py` L1877-1887, L951-958), so per-request mamba and draft blocks show up in the headline. `--block-size` cannot lower it (L909-915).

**Speculative decoding memory.** Draft TP defaults to target TP (`speculative.py` L1219-1222), so the 3.85 GB DFlash2 file is ~1.9 GB/rank plus ~0.5 GiB/GPU codebooks (**M**, README L36). Embeddings and lm_head are shared with the target when the draft lacks them (`llm_base_proposer.py` L1406-1407, L1424-1475); the drafter file (~1.9B params) cannot hold a 248,320 x 5120 embedding, so sharing applies (**E**). The draft's 5 attention layers (8 KV heads, window 2048) get their own group in the shared pool and inherit fp8 unless `"kv_cache_dtype"` is set inside `--speculative-config` (`speculative.py` L124-126). `n` grows the GDN conv rows (`mamba_utils.py` L260) and, mainly, `num_speculative_blocks = n` (`abstract.py` L74-78).

**Dead or wrong levers.** `--swap-space` no longer exists at v0.27.1 (replaced by `--kv-offloading-size/-backend`, `cache.py` L191-200, CPU prefix reuse only). `--cpu-offload-gb` is UVA weight offload re-read over PCIe every token (`offload.py` L23-32): decode collapse. `--max-num-seqs` only sizes graphs and GDN metadata (`gdn_attn.py` L119-160).

**Four cards.** `SupportsPP` is declared (`qwen3_5.py` L286-292), but embedding sharing is gated on PP world size == 1 (`llm_base_proposer.py` L1431), so PP 2x2 + DFlash2 is likely to fail; pool bytes equal TP4 anyway (**E**), the only upside is avoiding the 4-way PCIe all-reduce. DCP replicates mamba state (`kv_cache_interface.py` L741-742) and is refused by spec configs (`speculative.py` L990-994). `--enable-expert-parallel`, EPLB, `--moe-backend` are no-ops on a dense model. DP2 x TP2 doubles aggregate, not per-request.

**Suggested order:** #2 + #3, rebuild, read the three alignment log lines, then #1 in 0.02 steps, then #4, then #5 from the printed value.
